# SPEC-010：Codex 完成灯与长回合状态连续性

> 状态：done
> 类型：bugfix
> 需求来源：2026-10-19 用户反馈 Codex 未被监控，进一步澄清“只有运行的时候有，一旦结束就消失了”。
> 负责人：Codex
> 基线：`dbca9cf` + 保留 SPEC-009 等本地未提交修改；Windows 11 / Node 24.16.0。
> 需求依据及假设：沿用已有蓝灯运行、绿灯未确认完成、确认后灰灯、默认十分钟自动确认的规则；不新增永久绿灯语义。
> 关联/替代：替代 SPEC-002 中每轮从尾部空状态重建、所有历史 unknown 一律压过新完成的采集/聚合策略；不改变 TaskStore 非法转移与全局可见性规则。

## 1. 问题与目标

已观测的 Codex 回合结束后，被其他历史文件的 unknown/陈旧 running 压成 unknown，浮窗因此隐藏 Codex 行。每轮仅重放末尾 512 KiB 又会丢失长回合开始，导致运行/完成信息无法连续。目标是保留真实生命周期证据，完成后显示绿色，确认后显示空闲，不凭进程存在或普通正文猜测完成。

## 2. 范围与非目标

- 只改 Codex 只读采集与聚合、相关测试/说明；保留配置和已有其他修改。
- 不修改 Codex 源数据、认证文件、其他工具监控、共享状态机或浮窗隐藏规则；不引入依赖。
- 不承诺识别没有公开事件的审批等待、云端任务、压缩归档。

## 3. 验收条件

| ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-01 | 存在历史 unknown/启动前已陈旧 running，另一个回合有明确开始 | 本轮明确完成 | 显示 success、unread 和完成水位；重复轮询保持可见；确认/自动到期后 idle，不复亮 |
| AC-02 | 已观测多个新鲜并行回合 | 一个完成、另一个运行或随后失联 | 运行优先；已观测但失联的回合阻止冒充全部完成，不因历史文件无关错误洗绿 |

| AC-04 | 半行、超长正文、截断/替换、删除或目录错误 | 轮询/恢复 | 半行不提前生效；超长正文跳过但后续生命周期仍可读；源代际变化丢弃旧证据；失联如实 unknown，不把旧成功当新成功 |

边界：只看到完成而没有本回合开始，不制造 running 来绕过 unknown→success 禁令。启动前完成不重放；已有确认水位/十分钟到期不变。暂停恢复使用新监控器，重建只读基线。

## 4. 方案与切片

1. 先复现并修复聚合：区分历史噪声与本监控实际观测为活跃的回合；新完成不能被无关历史 unknown 抹去。
2. 再复现并修复长文件：每个候选文件保留有界的解析状态、读取游标和未完成短行；从头逐轮追平，然后只处理新增字节。首次追平前不发布不完整的历史状态；新增字节跨块时保留上一次可靠观测，不把读取预算造成的延迟当成失联。文件身份/长度/重写变化使缓存失效。最多缓存 32 个候选文件，不长期保留会话正文。
3. 类型检查、全量测试、构建、smoke，保留本机配置并只重启当前仓库实例，核对真实 UI。
