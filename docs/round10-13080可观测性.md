# 排查报告：13080「监控不到」—— 其实是**看不见**（round 10）

> 结论先行：**13080 一直在被正常监控**，只是界面上没有任何证据能让你确认这件事。
> 这是一个真实的可观测性缺陷 —— 我修的也是它，而不是监控逻辑。
> 日期：2026-10-14 · 结论：**442 测试全绿，五条实测链全通**

## 二、真正的问题：灰色 idle 无法与"没连上"区分

监控器本来就产出了关键证据：

```
message = "dsh 127.0.0.1:13080：64 会话"
```

但**这个字段在悬浮灯上完全不可见**：

- 灯带每行只显示「小圆点 + 端口号」
- 行的悬停文案只有 `task.name`（`dsh @ 13080（SSH 隧道）`）
- 总灯 tooltip 只显示**聚合计数**（"运行 1 · 等待 0"），没有逐端口信息

于是当四个灯全灰时，你无法区分这两种**完全相反**的情况：

| 情形 | 是否正常 | 原来能否看出来 |
|---|---|---|
| 连上了，但那个实例当前没有活跃会话 | ✅ 正常 | ❌ 看不出 |
| 根本没连上 / 没在监控 | ❌ 故障 | ❌ 看不出 |

**用户的原话是"好像没法监控到 13080"—— 监控正常，只是看不出来。**
这类"故障与正常长得一样"的设计缺陷，比真故障更消耗信任。

---

## 三、修法：把已有的证据暴露出来

### 3.1 每行悬停文案带明细

```ts
function describeTask(task) {
  const bits = [name, statusLabel(task.status)];
  if (task.message) bits.push(task.message);   // ← 关键：带上"64 会话"
  return bits.join(' · ');
}
```

结果：

```
13080  →  dsh @ 13080（SSH 隧道） · 空闲 · dsh 127.0.0.1:13080：64 会话
3080   →  dsh @ 3080（本机）      · 空闲 · dsh 127.0.0.1:3080：17 会话
```

### 3.2 总灯 tooltip 增加「各端口」段

```
○ 空闲
暂无运行中的任务

各端口：
· dsh @ 3080（本机） · 空闲 · dsh 127.0.0.1:3080：17 会话
· dsh @ 13080（SSH 隧道） · 空闲 · dsh 127.0.0.1:13080：64 会话
```

## 四、顺带发现并修正的一处口径不一致

写 tooltip 时我本想按「只列启用的任务」过滤，写成了 `t.enabled !== false`。
但 `TaskState` **没有** `enabled` 字段 —— 它有的是 `paused`（任务级手动暂停）。
配置里的 `enabled` 在 TaskState 上不保留。

这本来会被 TypeScript 拦下（`enabled` 不存在会报错），但我是在写代码时就意识到
应当与**灯带本身的口径**一致（灯带显示全部任务行，含配置中 `enabled: false` 的）。
所以改成 `t.paused !== true`，两者一致。

> 这也解释了为什么灯带上有 `dsh-plugin-3080` 这一行（它在配置里 `enabled: false`）——
> 那是有意行为：让"配置了但没开"也可见。若你希望它不显示，说一声即可。

## 七、还有一个值得你决定的小问题

既然 13080 的 64 个会话**全是 idle**，那盏灯就是灰的。
但"远端有 64 个会话，只是当前没活跃"和"本机 17 个会话"在灯带上长得一模一样。

如果你希望**一眼看出每个端口的规模**，有两个可选做法（都不改灯色语义）：

1. 灯带每行的端口号后面加一个很淡的会话数，如 `13080 ·64`
2. 只在有活跃会话时才在行尾显示数量徽标

现在至少悬停能看到了。要不要做进灯带本身，你定。
